#+title: Guix WSL Image

Guix System as a WSL2 distribution.  The release tarball is built by CI
from [[file:image.scm][image.scm]], which is [[file:wsl.scm][wsl.scm]] plus a first-boot step that installs
=wsl.scm= as an editable =/etc/config.scm=.

=wsl.scm= is the operating system from Guix's own =(gnu system images
wsl2)= with fixes for problems that otherwise show up after the first
restart or the first =guix system reconfigure= (see [[*What wsl.scm fixes][below]]).

* Install

In PowerShell, with the release tarball downloaded:
#+begin_src powershell
wsl --import Guix $HOME\Guix .\guix-wsl.tar.gz
wsl -d Guix
#+end_src

The first start boots the system and logs you in as =guest=, whose
password is empty.  sudo needs a password, so set one first, then
update and reconfigure:
#+begin_src shell
passwd                  # at "Current password", just press Enter
guix pull               # the image's own guix predates make-wsl-os
sudo guix system reconfigure /etc/config.scm
#+end_src

To use your own account, change =%user= in =/etc/config.scm= and
reconfigure.  The WSL default user stays =root= on purpose.  Root's login
shell is the boot program, which starts the system and then switches to
=%user= with sudo.  For a root shell that skips it:
#+begin_src powershell
wsl -d Guix -u root --exec /var/guix/profiles/system/profile/bin/bash
#+end_src

Boot output goes to =/var/log/wsl-boot.log=.

* Build it yourself

With Guix from 2026-09-17 or later (=make-wsl-os=):
#+begin_src shell
guix system image --image-type=wsl2 image.scm
#+end_src

Or stream it straight into WSL on a Windows machine you can SSH to:
#+begin_src shell
cat $(guix system image --image-type=wsl2 image.scm) | ssh windows-machine wsl --import guix 'C:\Guix' -
#+end_src

* What wsl.scm fixes

Each of these was reproduced on Guix master in October 2026.  The fix is
commented where it lives in =wsl.scm=.

- Lost boot after a restart.  Upstream writes =/etc/wsl.conf= with
  =[user] default=<user>=, so WSL starts the user's shell directly and
  root's boot program never runs.  After =wsl --terminate= or a reboot
  there is no =/run/current-system=, no shepherd, and nothing on PATH.
  /Fix:/ =default=root=.
- Shepherd dies with the first terminal.  The boot program starts
  shepherd inside the =wsl.exe= session that triggered the boot, and
  shepherd stops when that session ends.  /Fix:/ boot in a fresh
  session (=setsid=), with stdio on =/var/log/wsl-boot.log=.
- =guix system reconfigure= fails with "missing root file system":
  =make-wsl-os= declares no file systems.  A placeholder doesn't help.
  A fake device fails the device check, and =mount? #f= makes
  =store-file-system= raise.  /Fix:/ declare the device WSL actually
  mounted on =/=, read when the config is evaluated.
- No Windows interop in the first terminal after a restart.  Guix's
  boot-time cleanup deletes all of =/run=, including the booting
  session's =/run/WSL/<pid>_interop= socket.  /Fix:/ the same cleanup,
  minus =/run=, which WSL mounts fresh at every start anyway.
- =/mnt/c= unwritable, and =.exe= files not executable for the user.
  drvfs takes the WSL default user's uid, which is root here.  /Fix:/
  =[automount] options=uid=1000=.
- Shells start in =/root=, because WSL resolves =--cd ~= (Windows
  Terminal's default) for root.  /Fix:/ map =/root= to the user's home.
- No WSLg audio.  The final sudo keeps =DISPLAY= but drops
  =PULSE_SERVER=, =WSL_INTEROP= and friends.  /Fix:/ =env_keep= in
  sudoers.

Not fixed: =guix system roll-back= and =switch-generation= fail with
"dummy-bootloader: no such bootloader".  The WSL bootloader isn't one
=lookup-bootloader-by-name= can find.  To roll back, run
=sudo ln -sfn system-N-link /var/guix/profiles/system=, then
=wsl --terminate Guix=.
